启动时，能力如何装进工作区？

  1. Profile 选择运行方式

    Web 提供浏览器界面，headless 适合执行一次任务，SDK 面向程序调用，ACP 用于协议接入。每份配置都会列出要加载的组合包。

  2. Bundle 提供一组能力

    Web、headless、SDK 和 ACP 共用基础包，再加载各自的应用包。极简 SDK 单独组装。用户可以用配置补丁替换或加入插件。

  3. Cordis 挂载插件树

    插件向共享上下文注册服务、监听事件，卸载时撤销注册。模型适配器、工具表、会话日志，甚至驱动每一轮任务的循环都可以替换。

使用场景 / WORKFLOWS

把任务交给 Harness

选一个与你手头工作相近的任务，看看需要准备什么、会用到哪些工具，以及怎样验收结果。

修复仓库里的一处报错

给它什么　一个可运行的代码仓库、触发错误的输入，以及你期望看到的结果。

怎么做　在标准模式下让它先运行失败用例，再读相关实现、编辑文件并重跑测试。用代码差异视图逐行核对改动。

怎样验收　用相同输入重试。保留代码补丁、测试命令和退出结果，检查相邻功能是否仍能工作。

给销售报表补齐同比和环比

给它什么　一份至少覆盖十三个月的销售明细，指明按月份还是地区汇总，以及金额单位。

怎么做　先检查日期和缺失值，再分组计算。让它把对比期缺数或分母为零的行单独列出。

怎样验收　打开新工作簿，抽选一个地区，用原始明细复算连续两个月与去年同期的数据。

核对一份技术选型提案

给它什么　候选项目、必需功能和几项待核实的说法，例如某个版本能否恢复中断的会话。

怎么做　让它搜索上游文档和版本记录，把每项说法对应到具体版本、原文链接及适用条件。

怎样验收　检查对照表里的链接能否支撑结论，遇到文档未说明的功能，保留待验证项。

复盘一次走错方向的工具调用

给它什么　一个已有会话，以及首次出现偏差的位置，例如读错了同名文件。

怎么做　在 Trajectory 中定位那一轮，依次看当时的上下文、工具参数和返回内容。需要比较另一种做法时，从相关位置分叉。

怎样验收　记下出错的路径与调用次序，再比较两条分支的输出，确认哪一步改变了结果。

在极简环境中比较模型

给它什么　一组可独立评分的编码任务、初始文件和统一的评分规则。

怎么做　用 Minimal 预设限制工具集，为各任务分配独立的工作区和会话编号，记录模型设置与结果。

怎样验收　按同一规则汇总通过数，抽查失败轨迹，确认两个模型接触到相同的初始文件和工具。

场景依据　官方使用演示 · 轨迹与运行模式 · 基准测试说明

如何把社区索引接入自己的 Harness？
  1. 在目标配置档（profile）的「插件 → 实验性插件」中打开「自定义插件索引」。
  2. 进入「发现 → 添加索引源」，填入社区清单提供的地址，例如 https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json。
  3. 搜索插件，查看与当前宿主兼容的版本。点「安装」后核对 npm 包或 Git 提交，再确认安装。完成后在「已安装」查看组合包，按作者说明配置和启用。
